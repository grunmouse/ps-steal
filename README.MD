# steal.ps

Библиотека для PostScript, добавляющая в Ghostscript систему **вложенного импорта по относительным путям** — что-то вроде `require` / `include` для PS-проектов.

Ghostscript разрешает пути в `run` относительно текущего рабочего каталога, а не подключаемого файла. Из-за этого модуль, лежащий в подпапке, не может просто подключить соседний файл по относительному пути — всё ломается при вложенности. `steal.ps` решает это стеком базовых путей: каждый импортируемый файл может объявить свою базовую папку, и все импорты внутри него будут считаться от неё.

## Состав проекта

| Файл | Назначение |
|------|------------|
| `steal.ps` | Сама библиотека: стек путей, процедуры импорта, защита от повторного импорта |
| `pssteal.bat` | Запуск PS-проекта (Ghostscript, устройство `nullpage`) |
| `ps2pdf.bat` | Сборка PS-проекта в PDF (устройство `pdfwrite`) |

## Требования

- Ghostscript, утилита `gswin64c` в `PATH`, правильно сконфигурированая переменная `GS_LIB`.
- Для bat-файлов — Windows (cmd). Сама библиотека работает на любой платформе с любым Ghostscript.
- Bat-файлы запускают Ghostscript с ключом `-dNOSAFER` — без него `run` и `getenv` не работают. Запускайте только те PS-файлы, которым доверяете.

## Быстрый старт

```
myproject/
├── main.ps
└── modules/
    ├── core/
    │   ├── index.ps
    │   └── core.ps
    └── draw/
        ├── index.ps
        └── shapes.ps
```

```postscript
% main.ps — точка входа
(modules/core/) stealfolder
(modules/draw/) stealfolder

% дальше можно пользоваться определениями модулей
core_add 2 3 ==
```

```postscript
% modules/core/index.ps
(core.ps) stealfile        % разрешится как modules/core/core.ps
```

```postscript
% modules/core/core.ps
(core) declare-package     % защита от повторного импорта

/core_add { add } def
/core_mul { mul } def
```

### Запуск для отладки

```
pssteal.bat main.ps
```

### Генерация pdf

```
ps2pdf.bat main.ps out.pdf
```

## Нотация

В примерах используется стековая запись PostScript:

- `[basepath, filepath] steal` — состояние стека до вызова;
- `[]` — после вызова.

## Публичные процедуры

### `stealstart`

```
[путь к стартовому файлу] stealstart
[]
```

Точка входа проекта. Разбивает путь на папку и имя файла, сбрасывает стек путей, кладёт папку стартового файла как корневую базу и запускает файл. Вызывается **один раз** в начале работы — повторный вызов перезатирает состояние.

### `steal`

```
[basepath, filepath] steal
[]
```

Импортирует файл `filepath`, при этом `basepath` становится базой для всех относительных импортов внутри него. `basepath` обязан заканчиваться разделителем (`/`). Полный путь: `basepath + filepath` относительно текущей базы.

### `stealfile`

```
[filepath] stealfile
[]
```

Импортирует файл, не меняя базовый путь. Эквивалентно `[(./) filepath] steal`.

### `stealfolder`

```
[folderpath] stealfolder
[]
```

Импортирует модуль из папки: подключает `index.ps` в указанной папке и делает её базовым путём. Эквивалентно `[folderpath, (index.ps)] steal`.

### `ifnotkey`

```
[proc, key] ifnotkey
[результаты proc, если proc выполнялась]
```

Выполняет процедуру `proc` только если в `currentdict` нет ключа `key`. Если `proc` кладёт что-то в стек — оно остаётся. Удобно для защиты определений от повторного выполнения:

```postscript
{
    /helper { ... } def
    /helper2 { ... } def
} /helpers-loaded ifnotkey
```

### `declare-package`

```
[имя] declare-package
```

Регистрирует пакет: создаёт флаг `has-package-<имя>`. Если пакет уже зарегистрирован — вызывает `stop`, который перехватывается в `stealfile`, и **весь остаток импортируемого файла пропускается**. Поэтому `declare-package` пишут первой строкой модуля — это способ «импортировать файл только один раз»:

```postscript
/mymath declare-package
% ...все определения ниже будут выполнены только при первом импорте
/PI 3.14159265 def
```

Имя пакета — обычная PS-строка; избегайте пробелов и спецсимволов, т.к. она конвертируется в имя через `cvn`.

## Как это устроено внутри

- **`steal_stack`** — массив из 33 элементов, изображающий стек базовых путей. Ячейка 0 — корневая база (задаётся `stealstart`), вершина отслеживается `steal_stack_top`. Глубина вложенности — до 32 уровней.
- **`steal_push` / `steal_pop` / `steal_top`** — базовые операции стека.
- **`steal_join`** — склеивает все непустые элементы стека в строку `steal_path` (текущий полный базовый путь).
- **`steal_filepath`** — добавляет к текущему пути путь файла и возвращает готовый путь для `run`.
- **`steal_str_append`** — дописывает строку в строку-буфер с заданной позиции.
- **`steal_log` / `steal_log_append`** — журнал подключённых файлов (массив с автоматическим удвоением размера).

Все внутренние слова имеют префикс `steal_`, чтобы не конфликтовать с вашим кодом и стандартным PostScript.

## Ошибки

`stealfile` запускает файл внутри `{ ... run } stopped`. Если внутри импортируемого файла возникла **реальная ошибка** (`$error /newerror` = true), она пробрасывается дальше — наверх, к вызывающему коду или обработчику ошибок Ghostscript. Единственный «глушимый» стоп — тот, что порождает `declare-package` при повторном импорте.

## Ограничения и нюансы

- Полный путь собирается в буфер **512 байт** (`steal_path`). Более длинные пути дадут `rangecheck` на `putinterval`.
- Глубина вложенного импорта — **32 уровня** (переполнение стека путей — `rangecheck` на `put` в массив).
- Все базовые пути должны заканчиваться на `/`. `stealstart` сам приводит папку стартового файла к этому виду.
- Библиотека ожидает, что разделитель — `/`; bat-файлы перед запуском заменяют `\` на `/` в пути.
- Переменная окружения `STEAL_TARGET` используется bat-файлами для передачи пути: значение идёт через `getenv`, а не через строку `-c`, поэтому скобки и пробелы в именах папок безопасны.
